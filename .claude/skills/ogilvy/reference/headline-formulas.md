# Headline Formulas

Working patterns for headlines and subheads, with the failure modes each one avoids. Load when drafting or reviewing a headline, hero, or section head.

---

### Pain to Solution

Name the pain, then resolve it. The reader must feel the problem before hearing the answer.

```
[Pain point]. [Product] [fixes/solves/eliminates] that.
```

**Examples:**
- "Your cap table shouldn't require a finance degree. [Product] fixes that."
- "Fundraising data lives in 6 different tools. Not anymore."
- "Investors ask for documents you can't find. That ends today."

### Contrast

Set up the old way, then break from it. Creates a before/after in the reader's mind.

```
Stop [old way]. Start [new way].
```

**Examples:**
- "Stop emailing spreadsheets. Start sharing a live cap table."
- "Stop guessing which investors to contact. Start with data."

### Proof

Lead with a specific, verifiable number. Credibility first, explanation second.

```
[Specific number/result] [in timeframe].
```

**Examples:**
- "From first upload to investor-ready data room in 8 minutes."
- "87% of founders complete setup without support."

### Question

Ask what the reader is already thinking. Then answer it.

```
Why does [obvious thing] still [require pain]?
```

**Examples:**
- "Why does sharing a cap table still require exporting a spreadsheet?"
- "Why do founders spend more time on admin than fundraising?"

### Inevitability (Jobs-style)

Frame the product as the obvious next step. Not persuasion — declaration.

```
[Category] was always going to work this way. Now it does.
```

**Examples:**
- "Fundraising was always going to be a single workspace. Now it is."
- "Your data room, cap table, and pipeline in one place. Finally."
